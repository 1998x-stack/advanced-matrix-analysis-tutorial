CHAPTER 28 / ADVANCED MATRIX ANALYSIS

综合项目实战：图像压缩与推荐系统

两个项目共享同一数学核心——低秩矩阵近似。本文给出建模、公式与可复算的压缩率数值；涉及真实图像或评分数据的 RMSE 等结果，均标注为需自行运行复现，不转述未核实的数字。

01 / 把知识变成可运行的东西

前面 27 章讲的是概念与定理；本章把它们落到两个可运行的项目上。两者共享同一核心：把数据排成矩阵，用低秩分解寻找可以丢掉的部分。图像矩阵里可丢的是高频细节，评分矩阵里可丢的是噪声与冗余。

  • 项目 A： 用截断 SVD（以及可选的非负分解）对灰度图像做低秩近似，量化“压缩率”与“重构误差”的取舍。
  • 项目 B： 用截断 SVD 或交替最小二乘（ALS）在用户–物品评分矩阵上做协同过滤，用 RMSE 评估。
关于数字的纪律： 压缩率是由矩阵尺寸和秩直接算出的，可以复算；而重构误差、RMSE、训练时间取决于具体图像、具体随机划分与硬件，本页不转述具体数值。你需要用真实数据自行运行得到它们，并把结果当作你自己的实验结果。

本章代码依赖 NumPy/SciPy 或 scikit-learn；无法在此环境运行的部分已标注“未验证”。可复算的那一个（压缩率）用标准库给出。

02 / 项目 A：图像压缩与去噪

一张灰度图像可看作矩阵 A∈R^{m×n}，元素是像素灰度（如 0–255）。自然图像相邻像素高度相关，因此常具低秩结构。用截断 SVD 保留前 k 个奇异值：

A≈Ak=UkΣkVkT28.1

存储量从 mn 降为 k(m+n+1)（1 是 Σ_k 的 k 个奇异值，此计数为估计值），于是压缩率为

mnk(m+n+1)28.2

非负分解 A≈WH（W∈R^{m×r}_{≥0}, H∈R^{r×n}_{≥0}）同样可压缩，且因子非负、更可解释（第 20 章），但非负约束通常使同秩下的逼近误差大于 SVD。

import numpy as np

def svd_compress(A, k):            # A: 灰度图 (m,n)
    U, s, Vt = np.linalg.svd(A, full_matrices=False)
    return (U[:, :k] * s[:k]) @ Vt[:k, :]   # 秩-k 重构

def compression_ratio(m, n, k):
    return (m * n) / (k * (m + n + 1))

去噪： 噪声常表现为小奇异值对应的分量，丢掉最小的奇异值相当于低通滤波。一般存在一个中间 k 使重构质量最好——这是偏差–方差权衡在矩阵分析中的体现。具体最优 k 依赖图像与噪声水平，需自行实验，本页不给具体数字。

03 / 项目 B：基于矩阵分解的推荐系统

核心数据是用户–物品评分矩阵 R∈R^{m×n}，通常极度稀疏。矩阵分解假设用户偏好由少量潜在因子解释：

R≈PQT,P∈Rm×k,Q∈Rn×k28.3

预测评分 r̂_{ij}=p_iᵀq_j。只在已观测评分集 Ω 上最小化带正则的平方误差（ALS 的目标）：

minP,Q∑(i,j)∈Ω(rij−piTqj)2+λ(‖P‖F2+‖Q‖F2)28.4

ALS 交替固定 P 与 Q，每个子问题对每个用户/物品解一个小 k×k 线性系统（第 8 章的 Cholesky/LU 可用于此）。正则项 λ 控制因子范数、抑制过拟合。

import numpy as np
from scipy.sparse.linalg import svds

def svd_recommend(R, k):            # R: 评分矩阵，缺失处填 0（示例做法）
    U, s, Vt = svds(R, k=k)
    return U @ np.diag(s) @ Vt      # 返回稠密预测矩阵（小规模适用）

def rmse(obs_mask, R, Rhat):
    diff = (R - Rhat)[obs_mask]
    return float(np.sqrt(np.mean(diff ** 2)))
两种做法的差别： 直接用 svds 需要先把缺失值填 0，会引入偏差；ALS 只在观测集上优化，通常更准，但需迭代。具体 RMSE 取决于数据与划分，本页不给数值；请自行在 MovieLens 等公开数据上复现。

04 / 扩展：从矩阵到张量

两个项目都止步于矩阵分解。若数据自带第三个下标，可升级到张量分解（第 23–25 章），但“升级”意味着新的选择与代价，不是无条件的更好：

  • 图像 → 彩色/多维张量： 彩色图像是 m×n×3 张量，可用 Tucker/HOSVD 同时利用空间与通道结构。但 HOSVD 不是最优低秩逼近（第 24 章），且秩需逐模选取，实际收益取决于数据。
  • 推荐 → 张量推荐： 加入时间或上下文维得 用户×物品×时间 张量，用 CP/Tucker 捕捉偏好动态。代价是数据更稀疏、CP 秩难定且分解非凸。

其他可选的改进（均为工程建议，效果需自行验证）：

  • 用第 22 章的随机化 SVD 代替完整 SVD 以处理大规模矩阵（在大矩阵、低秩时通常更快）。
  • 引入隐式反馈（点击、时长等），用加权矩阵分解处理，把观测视为置信度。
  • 用第 21 章的矩阵补全（核范数最小化的凸松弛）处理缺失观测。
验证方式： 任何一条扩展都应在一个固定数据集、固定随机种子下与基线比较（同一评估指标、同一划分）。本页不预告“提升百分之多少”——那是实验的任务，不是文章的断言。

05 / 可复算算例：压缩率

用一个具体尺寸把压缩率公式算出来（标准库即可），核对“秩越大越不省空间”。

m = n = 200
for k in (2, 10, 20, 50):
    stored = k * (m + n + 1)
    print("k=%2d  存储=%5d  压缩率=%.2fx" % (k, stored, (m * n) / stored))

预期输出：k= 2 存储= 802 压缩率=49.88x；k=10 存储= 4010 压缩率=9.98x；k=20 存储= 8020 压缩率=4.99x；k=50 存储=20050 压缩率=2.00x。核对要点： 存储为 k(m+n+1)，压缩比为 mn/存储。失败模式： 若把存储误写成 k(m+n)（漏掉 k 个奇异值），会略微高估压缩率；当 k 接近 min(m,n) 时压缩率趋近 1，此时低秩近似已无优势。

k=10（m=n=200）：存储 4010 个，压缩率 9.98×。

该控件展示：秩 k 越大，存储越多、压缩率越低。这正是项目 A 中“压缩率 vs 重构质量”取舍的量化一面。默认状态无需脚本即可读出；键盘方向键可调 k。
